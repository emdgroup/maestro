Host
State Live: drag a tab to reorder it, onto the other side, or onto the right half of the file to split. Hover the file for its actions. Right-click a file or tab.
One component, both hosts
  • WorkspaceFilesPanel owns the tree, the tab rows, the groups and the split.
  • Each open tab is its own file pane (editor, draft, floating actions), kept mounted while hidden so drafts and scroll survive.
  • Hosts only pass a workspace, a connection, and a way in: openFile(path, lines?).
What differs per host
  • Files session: fills the session pane. Closing the session asks once if any tab is unsaved.
  • Side panel: Files becomes one tab, like Changes. A file link in the chat opens or focuses a file tab inside it and flashes the cited lines, instead of adding a new side-panel tab.
  • Narrow side panel: tree floats as an overlay. No split until the panel is maximized: no drop zone, and the menu items are disabled.
Split, by moving tabs
  • No split button. Tabs are dragged, or moved from their right-click menu (Move to the side, Move to the other side).
  • Drag along a tab row to reorder; onto the other side's row or file to move it there.
  • With one side, dropping a tab on the right half of the file opens the split with that tab. Needs at least two tabs.
  • A side whose last tab is moved out or closed goes away, and the split with it. Restoring a maximized side panel joins the sides.
Floating file actions
  • The band holds only what is not about one file: file list toggle, tree tools, tabs.
  • Edit and open in default app, or in edit mode the markdown layout, Save and Discard, float at the top right of the file they act on.
  • Copy path lives only in the tab's right-click menu.
  • Hidden until the pointer is over the file, almost transparent until it reaches the group, full on hover or keyboard focus. Same rule in each side of a split.
